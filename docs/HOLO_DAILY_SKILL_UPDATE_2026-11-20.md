8개 영상 카테고리(광고·브랜드, 시네마틱, 숏폼, 제품·푸드, 인물·캐릭터, 애니·판타지, 패션·뷰티, 아트·실험)를 검토. 기존 11월 10~19일의 제품 교체, 버전 고정, 동작 명료화, 화면비, 레이어, UGC, 관절 적합성, 멀티컷, 프롬프트 확장, HDR, 3앵커 스킬과 구분한다. 오늘 채택 1개는 **모델 선택 전 능력·비용·품질 제약 검사**이다. 신기능 출시일과 조사일은 구분한다.

## 신규 스킬 — Capability-Constrained Model Routing & Dry-Run Gate
- **핵심 원리:** 모델 라우터가 비용·지연·품질 기준으로 공급자를 선택하기 전에 필수 입력 및 출력 능력(참조 이미지/영상, 길이, 화면비, 오디오, 제품·인물 일관성)을 만족하는 후보만 허용한다. 라우팅을 사전 미리보기(dry run)로 점검하고, 모델/라우팅 설정과 선택 결과를 기록한다. Runway Dev는 2026-07-23 Model Router의 저장된 configId, 허용/차단 목록, 모달리티별 크레딧 상한, dryRun을 공식 발표했다. **이는 Runway Dev의 기능이며 HOLO MiniMax 직접 API의 내장 기능이 아니다.**
- **적용 조건:** 복수 모델을 실제로 연결하고, 각 모델의 지원 능력과 비용표가 검증되었으며, 프로젝트가 특정 품질·예산·출력 조건을 명시할 때. 단일 MiniMax만 연결된 상태에서는 모델 전환 없이 '사전 적합성 체크리스트'로만 적용.
- **좋은 예:** 12초 세로형 뷰티 광고: 9:16, 제품 정면 라벨 보호, 승인된 인물 이미지, 한국어 멘트, 최대 예산을 필수 조건으로 기록. 지원되지 않는 오디오/참조 입력 모델은 후보에서 제외하고, dryRun으로 경로를 확인한 뒤 소규모 샘플 검수. 실제 한국어 음성·얼굴·라벨 품질은 생성 후 별도 판정.
- **피해야 할 경우:** 비용만 보고 인물 참조 미지원 모델로 자동 변경, 검증되지 않은 모델의 한국어 음성 품질을 보장한다고 주장, dryRun을 실제 품질 검증으로 간주, 제공되지 않는 파라미터를 MiniMax 직접 API에 전송, 민감한 광고를 승인 없이 자동 배포.
- **제안 QA 필드(미구현):** project_id, required_capabilities, allowed_models, excluded_models, reference_asset_versions, cost_ceiling, router_config_version, dry_run_result, selected_model, expected_output_spec, identity_QA, product_label_QA, Korean_audio_QA, human_approval.
- **기존 스킬과 차이:** 11월 11일의 버전 고정은 선택된 제작 경로의 재현성을 다루며, 이번 스킬은 **생성 전 모델 선택의 제약 충족과 예산 통제**를 다룬다. 11월 17일 프롬프트 확장 비교와도 별개이다.
