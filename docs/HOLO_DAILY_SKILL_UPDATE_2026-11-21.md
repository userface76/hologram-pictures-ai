# HOLO AI Daily Skill Update — 2026-11-21 (KST)

## 조사 및 중복 판정
8개 카테고리(광고·브랜드, 시네마틱, 숏폼, 제품·푸드, 인물·캐릭터, 애니·판타지, 패션·뷰티, 아트·실험)를 검토. 기존 11월 11~20일 버전 고정, 동작 명료화, 결과물 화면비 재구성, 원본 수정 강도, 레이어, UGC, 동작 전이, 멀티컷, 프롬프트 확장, HDR, 3앵커, 모델 라우팅과 비교. 신규 1개 채택: **생성 입력 단계의 중앙 크롭과 참조 피사체 안전영역 검사**. 11월 12일의 *생성 후 결과물 재프레이밍*과 구별.

## 신규 스킬 — Reference Input Crop-Safety & Aspect Preflight Gate
- **핵심 원리:** 생성 요청 화면비와 참조 이미지의 화면비가 다를 때 입력이 중앙 크롭될 수 있다. Runway Dev 공식 API 입력 명세는 MiniMax H3의 `ratio` 지원값(`adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`)과 입력이 요청 비율에 정확히 맞지 않으면 중앙 크롭된다고 명시한다. `adaptive`는 참조 이미지/영상이 필요하다. 이는 Runway Dev 경로의 명세이며 HOLO의 MiniMax 직접 API에 동일 규칙이 적용되는지는 별도 확인 필요.
- **적용 조건:** 인물 얼굴, 제품 라벨, 손, 브랜드 로고가 참조 프레임 가장자리에 있거나 입력 화면비와 출력 화면비가 다를 때. 생성 전 목표 비율의 실제 크롭 미리보기를 만들고 얼굴/손/로고/제품의 바운딩 박스가 보존되는지 확인한다.
- **좋은 예:** 16:9 원본 세럼 광고를 9:16로 생성하기 전, 중앙 크롭 미리보기에서 제품 병과 모델 얼굴이 동시에 들어오는지 검사. 둘 다 보존되지 않으면 무작정 생성하지 않고, 사전 재구도/패딩 또는 별도 승인된 9:16 참조를 제작한다. 라벨의 글자와 용기 모양은 생성 후에도 별도 QA.
- **피해야 할 경우:** 중앙 크롭으로 손이나 제품이 잘리는 상태에서 반복 생성; 제품을 AI 확장해 가짜 라벨을 만들고 승인 없이 광고에 사용; 공급자별 입력 처리 차이를 무시; 패딩이 실제 모델에서 그대로 유지된다고 보장.
- **제안 QA 필드(미구현):** source_aspect_ratio, target_aspect_ratio, provider_model, crop_policy_verified, crop_preview_uri, face_safe, hands_safe, product_safe, logo_safe, approved_reference_version, post_generation_QA.
- **중복 회피:** 11월 12일 스킬은 생성된 영상의 16:9→9:16 *후처리* 안전영역 검사. 이번 스킬은 생성 *이전* 입력 참조가 모델에 전달될 때 잘릴 수 있는 위험을 사전 차단한다.
