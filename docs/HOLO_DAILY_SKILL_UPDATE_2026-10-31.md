## 1. Audio Rhythm Reference Contract — 오디오 참조 기반 장면 리듬 고정

### 핵심 원리
Runway의 *Creating with Minimax H3* 공식 가이드는 Minimax H3 워크플로에서 **오디오 참조를 영상 생성의 pacing/rhythm을 유도하는 입력**으로 지원한다고 설명한다. 이미지 참조(대상), 영상 참조(카메라 움직임), 오디오 참조(리듬)의 책임을 분리할 수 있다. 이는 기존 'Korean Dialogue Duration Gate'(대사 길이 적합성 검사) 및 'MiniMax Korean Speech Locale & Pause Contract'(별도 TTS 언어/쉼 API 제어)와 다르다. **오디오 참조는 한국어 발음이나 언어를 고정한다는 근거가 없다.**

### 적용 조건
- 장면의 컷/동작 리듬이 중요한 광고, 숏폼, 제품 시연, 패션 런웨이, 뮤직/아트 영상.
- Runway에서 제공하는 Minimax H3 인터페이스 기준 오디오 참조는 최대 3개, 각 2~15초. 첫/마지막 키프레임 입력과 레퍼런스 입력은 결합 불가.
- **HOLO의 직접 MiniMax API 어댑터가 같은 오디오 참조 입력을 지원하는지는 미확인**. 지원 여부 확인 전에는 자동 API 필드 전송을 하지 않는다.

### 좋은 예시
10초 세럼 광고에서 제품 이미지는 브랜드 정체성, 10초 카메라 샘플은 움직임, 10초 저작권/사용권을 확보한 음성 또는 박자 참조는 느린 장면 리듬을 담당한다. 화면 전환과 손동작의 템포만 유도하고 한국어 내레이션의 정확한 발화는 별도 TTS+QA로 관리한다.

### 피해야 할 경우
- 빠르게 말하는 참조 음성을 사용해 과속 대사 문제를 해결하려는 경우.
- 오디오 참조만으로 한국어 음성 정확도/립싱크가 보장된다고 주장하는 경우.
- 저작권/초상·음성 권한을 확인하지 않은 음악·타인 음성.
- 키프레임과 레퍼런스를 동시에 보내는 요청(해당 Runway H3 워크플로에서 지원하지 않음).
- 모델마다 참조 한도·비용이 같다고 가정하는 경우.

### 검증/수용 기준
같은 영상 프롬프트·길이·제품 이미지를 고정하고 (A) 오디오 참조 없음 (B) 느린 리듬 참조를 비교한다. 컷/동작 변화 간격, 제품 정체성, 발화 속도, 언어 혼입, 생성 비용을 기록한다. 효과 미확인 시 프로덕션 기본값에 적용하지 않는다.

  - 5~15초 출력, 오디오 참조 2~15초/최대 3개, 오디오 참조의 pacing/rhythm 역할, keyframe/reference 동시 사용 불가 (Runway 인터페이스 기준).

## 2. Identity-Safe Aspect Reframe Gate — 인물·제품 정체성 보호형 화면비 재구성

### 핵심 원리
Luma Agents 공식 Ray 3.2 **video_reframe**은 기존 클립의 원본 프레임 내용을 보존하면서 화면비 변경으로 새로 노출되는 주변 캔버스를 확장(outpaint)하는 워크플로다. 새로 만들어진 영역의 인물/제품/텍스트를 검수하고, 원본 핵심 피사체를 보존해야 한다. 단순 크롭과 AI 리프레임을 구분한다.

### 적용 조건
- 같은 16:9 원본을 9:16 쇼츠, 1:1 피드 등으로 재활용할 때.
- 제품 용기/얼굴/로고/손이 프레임 경계에 가까운 장면.
- **Luma Ray 3.2 별도 API 경로**를 사용할 때: `model: ray-3.2`, `type: video_reframe`, `source`, `prompt`, `aspect_ratio`. HOLO MiniMax H3 자체 기능으로 오인하지 않는다.
- 공식 제한: 원본 및 출력 최대 10초. 긴 영상은 10초 이하로 분할해 처리하고 연결 경계 검수. 세로 9:16/3:4 출력은 문서 기준 1080p 미지원(720p 등 사용). 소스 URL 사용 시 `source.media_type: video/mp4` 등 지정. `video.source_position`으로 원본 배치 제어 가능.

### 좋은 예시
16:9 세럼 광고를 9:16 쇼츠로 바꿀 때 먼저 일반 크롭에서 병·얼굴·로고가 안전영역에 들어오는지 검사한다. 크롭으로 보존 불가능할 때만 승인된 원본 클립을 Ray 3.2 video_reframe에 보내고, 제품 병은 원본에 유지하면서 바깥 배경만 확장하도록 프롬프트를 작성한다. 결과에서 로고·용기 형태·인물 얼굴·손·배경 경계·시간축 일관성을 검수한다.

### 피해야 할 경우
- 원본이 이미 9:16에 잘 맞는데 비용이 드는 AI 리프레임을 불필요하게 실행.
- 리프레임으로 생성된 화면 가장자리의 추가 인물·손·상품·로고를 검수 없이 승인.
- 긴 클립을 분할하지 않고 10초 제한을 초과해 제출.
- `video_edit`와 `video_reframe`을 같은 작업으로 취급.
- 세로 1080p가 지원된다고 가정하거나, 원본 오디오/자막 보존까지 자동 보장한다고 단정.

### 검증/수용 기준
(A) 크롭 (B) AI 리프레임 비교. 피사체 가시성, 얼굴·제품 정체성, 로고/텍스트 오류, 새 영역 아티팩트, 클립 이음새, 실제 비용/소요시간을 기록. 브랜드·제품 일치 실패 시 자동 게시 금지.

## 변경 전후 요약
- **이전:** 제품 원본 품질 → 모션 충돌/대사 길이 검사 → 생성 → 한국어 TTS 및 클립 연결 QA.
- **이후:** 기존 과정 유지 + (지원 모델에서만) **오디오 참조를 별도 리듬 제어 신호로 사용** + 배포 포맷 변환 시 **단순 크롭 우선, 필요한 경우 AI 리프레임과 정체성 검수**.
- **중복 방지:** 오디오 참조는 대사 언어/속도 API 제어가 아닌 영상 리듬의 입력이다. 리프레임은 클립 연결이 아닌 화면비 변환과 주변 캔버스 확장이다.
- **검증 상태:** 공식 제공 기능 확인 / HOLO API 연동, 비용 절감 효과, A/B 테스트 및 서비스 배포 **미실시**. 별도 공급자 연동에는 비용과 구현 작업이 필요하다.
