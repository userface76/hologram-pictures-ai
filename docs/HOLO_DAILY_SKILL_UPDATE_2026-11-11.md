## 신규 스킬 1 — Version-Pinned Creative Workflow Reproducibility
- **원리:** 여러 단계의 이미지→영상→편집 워크플로는 공급자의 최신 기본 버전이 바뀌면 동일 입력에서도 구성/출력이 달라질 수 있다. Runway Dev Workflows는 노드 그래프를 버전 지정 엔드포인트로 공개하며, Multi-Shot Recipe도 `version: "2026-06"` 같은 고정 버전을 지원한다.
- **조건:** 반복 제작하는 브랜드 광고, SKU 캠페인, 승인된 프리셋. 모델·API·레시피 버전, 참조 에셋 식별자, 프롬프트, 시드(지원 시), 화면비, 길이, 후처리 설정을 작업별 매니페스트로 보관.
- **좋은 예:** 15초 세럼 광고 10편의 컷 구성을 동일한 레시피 버전으로 실행하고 승인된 모델/제품 이미지 및 설정의 변경 이력을 남김.
- **피할 것:** `unsafe-latest`를 상용 승인 캠페인의 기본값으로 사용하거나, 시드만으로 픽셀 단위 재현성을 보장한다고 주장하는 경우.
- **QA:** workflow_version, provider_model, model_version_if_available, reference_asset_ids, prompt_hash, seed_if_supported, output_spec, approval_id, diff_summary.
- **기존 스킬과 차이:** 모델 호환성/비용 사전검사는 '실행 가능 여부'이고, 이번은 **시간이 지나도 설정과 변경 이력을 추적할 수 있는 재현성**.
- **근거:** Runway Dev API Changelog 2026-10-26 (Workflows guides), https://docs.dev.runwayml.com/api-details/api_changelog/ ; Multi-Shot Recipe https://docs.dev.runwayml.com/recipes/multi-shot-video/ (2026-11-11 확인).

## 신규 스킬 2 — Physical-Action Prompt Clarity Gate
- **원리:** 생성 모델에 감성적 추상어만 제시하기보다 화면에서 확인할 수 있는 주체·동작·방향·속도·카메라 상태를 긍정형 문장으로 지정한다. Runway Gen-4 가이드는 직접적이고 구체적인 물리적 동작 묘사 및 긍정형 표현을 권장한다.
- **조건:** 모델이 모션을 잘못 해석하거나 카메라가 의도치 않게 움직이는 장면. 기존 승인 인물·제품·한국어 대사 원문은 그대로 유지하며 **동작 문장만** 명료화.
- **좋은 예:** '고급스럽고 역동적인 세럼 광고' 대신 '카메라는 고정. 오른손이 세럼 병을 5cm 들어 올리고 1초 정지. 제품 라벨이 정면을 향한다.'라고 동작을 명시(수치의 정확한 준수는 보장되지 않음).
- **피할 것:** 한 컷에 여러 상충하는 행동, 금지어 반복, 과도한 정밀 수치 강요, 제품/얼굴 설정의 임의 수정.
- **QA:** visible_subject, observable_action, motion_direction, camera_state, conflicting_actions, locked_identity_diff, output_motion_review.
- **기존 스킬과 차이:** 모델별 카메라 명령어 검증은 지원 토큰 검사이며, 이번은 **동작 서술의 관찰 가능성과 모호성 제거**.
- **근거:** Runway Gen-4 Video Prompting Guide https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide (2026-11-11 확인). 모델별 효과는 별도 검증.

## 변경 전후 및 운영
- 이전: 입력/모델 적합성 검사 → 생성 → 인물/제품/대사/색상/납품 QA.
- 이후(문서상): **버전/참조/승인 매니페스트 기록** → 기존 적합성 검사 → **동작 문장 명료성 검사** → 생성 → 기존 QA 및 변경 이력 비교.
- 공급자별 지원 차이 확인 후 선택적으로 적용. MiniMax H3 직접 API 지원을 추정하지 않음. 생성 코드·운영 배포·A/B 테스트는 변경하지 않음.
